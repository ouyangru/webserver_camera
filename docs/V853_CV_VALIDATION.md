## 正确性与隔离

本项目交叉编译的 worker 处理官方 `body_384x216.yuv`：检出2人，分数约0.637和0.879。
将相同输入在PC逐像素旋转90°，板上以 `CV_ROTATE=270` 处理，仍检出同样2人，分数一致，框正确逆变换到216×384原图。
此结果验证推理执行、NV12方向处理和坐标映射；只有一张标准测试图片，不构成场景准确率评估。

停止推理服务后，API报告推理不可用，FLV源仍ready；随后重启推理可恢复。重启板子后无需手动运行程序。
浏览器实际读取到640×480视频、readyState=4、paused=false，播放时间持续前进。最终截图中镜头朝向桌面，未检测到人符合画面内容。

运行 `tests/cv_live_smoke.py http://127.0.0.1:18080 60 REPORT.json`，共30次状态采样，耗时60.6秒。

这组数据使用USB转发，不能用于断言Wi-Fi或完整摄像头到屏幕延迟。CPU分别计量两个进程，RSS不涵盖全部DMA/ION/NPU预留内存。
最近结果叠加尚未与浏览器视频逐帧同步。

另外使用 ffmpeg 从实际 `/live.flv` 连续解码3秒，退出码0，错误日志为空。
主机HTTP/FLV/本地资源冒烟通过100次请求，RSS6176→6184kB；主机未装JPEG开发头，冒烟编译关闭JPEG，板端交叉编译开启JPEG和Cedar。
最终独立worker构建与Tina包编译退出码均为0；`git diff --check`通过。
